# Agent Study — IST Chebyshev GCN HPO analysis and refined fine-tune

Date: 2026-11-20. Scope: seeds 0–19 only (no confirmatory seeds 100+).
All artifacts live in `hpo_out/agent_study/`. Drivers: `build/agent_refine_sweep.py`,
`build/agent_vectorize.py`.

## 1. What the 100-trial matrix shows

`hpo_matrix.csv` is the cleaned trials×(params+metrics) matrix with derived
columns `val_loss_delta_vs_baseline`, `recovery_delta_vs_baseline`,
`recovery_rank` and `region`.

**Correlation structure.** Across all 100 trials, val-loss delta vs baseline
and recovery delta correlate at **r = −0.58**: lowering the surrogate val
loss almost monotonically costs swarm recovery. The val-loss surface's minimum
and the recovery surface's maximum point in opposite directions — this is the
"surrogate-optimization failure mode" named in `hpo_out/REPORT.md`, visible
directly in the matrix rather than only at the best trial.

**Region rule** (used for the `region` column):
- `trap` — val_loss_delta < −0.1 **and** recovery_delta ≤ −0.1
- `safe` — val_loss_delta < 0 **and** recovery_delta ≥ −0.1
- `neutral` — everything else (val-loss-neutral or recovery-degrading configs)

Counts: **72 trap, 28 neutral, 0 safe.** The zero count is the finding:
*nowhere in the 100-trial TPE sample does a config improve the surrogate val
loss without losing at least 0.1 of recovery* (the best val-loss-improving
trials all sit at recovery 0.6–0.8 vs baseline 0.9 on the same folds).

**Trap-region signature.** Grouping by architecture:

| hidden | layers | n | mean rec | mean val-loss delta |
|---|---|---|---|---|
| 128 | 6 | 43 | 0.623 | −0.283 |
| 128 | 10 | 24 | 0.633 | −0.291 |
| 128 | (4/8) | 7 | ~0.43–0.63 | −0.04…−0.14 |
| 256 | any | 9 | ~0.60–0.63 | −0.01…−0.34 |
| 512/768 | 8 | 3 | 0.600–0.900 | −0.02…0 |
| 512×10, 768×10, 768×4 | | 5 | 0.40 | +0.39…+0.60 |

The trap is not a single point but a connected region: **hidden 128, deep
(6–10 layers), dropout 0.2 and/or val_frac 0.2 with max_epochs 40** — i.e.
small, heavily-regularized, early-stopped networks. All 8 lowest-val-loss
trials have hidden=128, 6–10 layers, val_frac 0.2, max_epochs 40. Recovery
rises steadily with hidden size at fixed depth, and the only 512×8 sample in
the whole study is the baseline itself (recovery 0.9, best in matrix).

**Safe region.** The safe region is the baseline's immediate neighborhood:
512×8, low lr, no dropout, no val split, few epochs (5). The TPE, optimizing
val loss, never samples there except at trial 0. Note (from
`build/agent_refine_sweep.py`): 10 of 12 lr×wd perturbations *around* the
baseline already lose recovery on seeds 0–4 — the basin is narrow.

## 2. Refined fine-tune (deliverable 3)

**Selection rule (stated before running):** among the 12 configs whose mean
recovery on seeds 0–4 is within 0.02 of the baseline's mean recovery on the
same seeds, pick the lowest mean val loss.

Grid: lr ∈ {5e-5, 1e-4, 2e-4, 5e-4} × wd ∈ {0, 1e-5, 1e-4}, hidden 512,
layers 8, dropout 0.0, max_epochs 5, val_frac 0.0, via `build.hpo_gcn.episode`
(spawn Pool of 5, `torch.set_num_threads(1)` in workers).

Results (seeds 0–4): baseline rec **1.000**, mean val loss **86.2298**.
Only three grid configs kept recovery 1.000: (lr 1e-4, wd 0) — the baseline
itself — (lr 1e-4, wd 1e-4) with identical val loss 86.2298, and every other
perturbation dropped to 0.4–0.8. Tie broken by grid order →

**Refined config = the baseline:** `{lr: 1e-4, hidden: 512, layers: 8,
wd: 0.0, dropout: 0.0, max_epochs: 5, val_frac: 0.0}`.

Held-out check (seeds 5–9, reported only, no re-selection): chosen vs
baseline — recovery **0.800 vs 0.800**, mean val loss **86.6782 vs 86.6782**
(identical, as expected since the refined config equals the baseline).
Full numbers in `refined_cfg.json`.

Conclusion: consistent with REPORT.md — the baseline is a local (and the only
sampled) system-optimal point; the val-loss surrogate offers no usable
gradient toward it from anywhere that was sampled.

## 3. Reproduce

```bash
# refined sweep (12 configs x seeds 0-4, held-out 5-9; ~3-10 min, 5 workers)
python build/agent_refine_sweep.py

# canonical vectors + distances (reads agent_study/refined_cfg.json)
python build/agent_vectorize.py

# cleaned matrix (pandas one-liner equivalent is in git history; the file
# itself is regenerated by the analysis that produced STUDY.md section 1)
```

Determinism: `torch.manual_seed(init_seed)` before every ChebNet construction
(the HPO driver seeds after controller construction post-fix); spawn-context
Pool; single-threaded torch in workers.
